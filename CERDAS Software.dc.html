How we release software

Research code is only useful if someone else can run it. Four rules apply to everything on this page.

01
A licence, always
No unlicensed drops. Permissive by default; copyleft where a funder or dependency requires it.
02
A DOI to cite
Every release is archived and citeable, so the people who wrote the code get credit in the literature.
03
A named maintainer
One person is responsible for issues and releases. When they move on, the package is handed over or archived honestly.
04
Runnable from the paper
If a publication depends on the code, the release that produced its results stays available and tagged.
